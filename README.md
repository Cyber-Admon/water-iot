# IoT Water Pollution Monitoring System

Final year project: ESP32-based water quality monitoring using turbidity, pH, TDS,
and temperature sensors, transmitting data to a FastAPI backend for storage,
threshold evaluation, and dashboard display.

## Architecture

Five-layer IoT reference architecture:

1. **Perception Layer** — ESP32 + turbidity, pH, TDS, DS18B20 temperature sensors
2. **Network Layer** — WiFi (development) / GSM-4G (field deployment)
3. **Middleware Layer** — FastAPI backend, validation, Postgres, WHO threshold comparison, alert logic
4. **Application Layer** — API endpoints, web dashboard
5. **Business Layer** — Evaluation metrics (accuracy, reliability, response time, usability)

Built using an Incremental SDLC model. See project docs for the full layered
architecture diagram.

## Running the Backend Locally (Docker)

1. Make sure Docker Desktop (with WSL2 backend on Windows) is running.
2. From the project root:

```bash
docker compose up --build
```

3. Backend will be available at `http://localhost:8000`
4. Interactive API docs (auto-generated by FastAPI): `http://localhost:8000/docs`

First build takes a few minutes (installing dependencies). After that, only
your code changes trigger rebuilds, and those are fast because dependencies
are cached in their own Docker layer.

## Testing Without Any Hardware

Run the simulator to send fake sensor readings straight to the backend:

```bash
cd backend
pip install requests
python simulator.py
```

Then check `http://localhost:8000/api/readings/latest` to see the data arrive.

## Testing With the ESP32 (Simulated Sensor Values)

1. Open `firmware/water_monitor_esp32/water_monitor_esp32.ino` in Arduino IDE
2. Install the ESP32 board package and the `ArduinoJson` library
3. Update `WIFI_SSID`, `WIFI_PASSWORD`, and `SERVER_URL` (use your computer's
   local IP address, not `localhost`, since the ESP32 is a separate device
   on the network)
4. Upload to the ESP32, open Serial Monitor at 115200 baud
5. Watch simulated readings get sent every 60 seconds and confirm they appear
   in the backend

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/readings` | Submit a new sensor reading |
| GET | `/api/readings` | List readings (optional `node_id`, `limit` filters) |
| GET | `/api/readings/latest` | Latest reading per node |
| GET | `/api/nodes` | List all registered nodes |
| GET | `/api/alerts` | List threshold-breach alerts |
| GET | `/api/stats/reliability` | Transmission reliability metric (Objective iv) |

## WHO-Referenced Thresholds Used

| Parameter | Safe | Warning | Danger |
|---|---|---|---|
| Turbidity | ≤ 5 NTU | 5–10 NTU | > 10 NTU |
| pH | 6.5–8.5 | 5.5–6.5 or 8.5–9.5 | outside 5.5–9.5 |
| TDS | ≤ 500 ppm | 500–1000 ppm | > 1000 ppm |

## Build Plan (Incremental SDLC)

- **Increment 1**: Backend + dashboard, fully working with simulated data (current phase)
- **Increment 2**: Real sensors wired on breadboard, one at a time, replacing simulated values
- **Increment 3**: GSM/4G module added for field deployment
- **Increment 4**: Evaluation — sensor accuracy, transmission reliability, response time, usability testing
